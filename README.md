# Система учёта питания в столовой

Учебное приложение для учёта питания в столовой. В ПР №5 добавлен
веб-интерфейс Django на основе объектной модели ПР №3. В ПР №6 добавлены
шаблон карточки заказа, общие компоненты и локальные статические файлы.
В ПР №7 веб-версия перешла на SQLite и получила поиск по дате и статистику.
В ПР №9 модели Django и ORM заменили прямые SQL-запросы представлений.
В ПР №10 добавлены Django Admin, история заказов со статусами и адреса блюд по slug.

## Возможности консольной версии

- Добавление посетителей и поиск по части имени без учёта регистра.
- Просмотр меню по алфавиту, цены и доступности блюд.
- Просмотр, оформление и отмена заказа посетителя.
- Подсчёт действующих заказов и их общей стоимости.
- Сохранение изменений между запусками.

У посетителя может быть один действующий заказ на одно блюдо.
Для оформления заказа нужно зарегистрировать посетителя и выбрать доступное
блюдо. Цены указаны в долларах, как в исходном примере.

## Веб-интерфейс

Для запуска нужен Python 3.10 или новее. В каталоге проекта выполните:

```bash
python3 -m pip install -r requirements.txt
python3 manage.py migrate
python3 manage.py check
python3 manage.py runserver --insecure
```

Для первого заполнения базы выполните перенос из ПР №7 по шагам ниже.
Откройте [главную страницу](http://127.0.0.1:8000/). Веб-интерфейс читает
`db.sqlite3`. Изменения заказов в этой базе выполняются командами Django.

Флаг `--insecure` включает раздачу CSS, JavaScript и изображения локальным
сервером при `DEBUG=False`. Этот режим позволяет одновременно проверить
собственную страницу 404 и статику на компьютере разработчика.

| URL | Страница |
| --- | --- |
| `/` | Главная страница с навигацией |
| `/menu/` | Меню, поиск по названию и доступность на дату |
| `/menu/dish/pizza/` | Карточка блюда по slug. Старый адрес `/menu/Pizza/` перенаправляет на неё |
| `/orders/` | Заказы с фильтрами по блюду, дате и статусу, поиском, сортировкой и пагинацией |
| `/orders/Alice/` | Действующий заказ посетителя |
| `/orders/id/1/` | Карточка заказа по ID, включая отменённые и выполненные |
| `/admin/` | Администрирование блюд, посетителей, заказов и исключений по датам |
| `/statistics/` | Количество посетителей, цены, итоги и группировки заказов |

Неизвестный адрес, блюдо или заказ возвращает страницу с кодом HTTP 404.

### Шаблоны и маршруты

Представления вызывают `render()` и передают объекты в контекст. Страницы
наследуют `base.html` и заполняют блоки `title` и `content`. Навигация
и подвал подключаются через `include`. Списки используют `for`, проверки
`if` и ветки для пустых коллекций. Фильтры `length`, `floatformat` и
`default` форматируют значения. Ссылки формируются тегом `url` с именами
и пространствами имён `homepage`, `menu` и `orders`.

### Статика

Django находит CSS, логотип и JavaScript в `homepage/static/homepage/`.
Они подключаются тегом `static`. CSS оформляет навигацию и карточки,
JavaScript выводит текущий год в подвале. Bootstrap подключён через CDN.
Представления передают в шаблоны объекты моделей и результаты Django ORM. Общий процессор контекста
передаёт название столовой в шаблоны.

## Запуск консоли

Для работы нужен Python 3.10 или новее. В каталоге проекта выполните:

## Объектная модель

| Класс | Атрибуты и поведение |
| --- | --- |
| `Visitor` | Хранит имя `name`. Метод `__str__` возвращает это имя. |
| `Dish` | Хранит название `name`, цену `price` и доступность `available`. Метод `__str__` формирует описание для меню. |
| `Order` | Связывает посетителя `visitor` и блюдо `dish`. Метод `__str__` формирует описание заказа. |
| `Canteen` | Хранит словари объектов `visitors`, `menu` и `orders`. |

Методы `Canteen.add_user()` и `Canteen.find_users()` добавляют и ищут
посетителей. `Canteen.add_order()` проверяет доступность блюда и связывает
в заказе объекты из двух коллекций. `Canteen.info_user()` показывает заказ,
`Canteen.cancel_order()` удаляет его, а `Canteen.order_statistics()`
подсчитывает количество заказов и суммирует цены их блюд.

## Структура моделей Django

Веб-данные хранятся в SQLite `db.sqlite3`. Миграции создают таблицы Django
и собственную историю схемы. У каждой модели автоматически создаётся
первичный ключ `id` типа `BigAutoField`.

| Модель | Поля и связи |
| --- | --- |
| `Visitor` | Уникальное имя |
| `Dish` | Уникальные название и slug, описание, неотрицательная цена, доступность и необязательный дневной лимит порций |
| `Order` | Внешние ключи на посетителя и блюдо с `PROTECT`, дата и статус. Обратные связи `visitor.orders` и `dish.orders` |
| `DishUnavailability` | Дата и `ForeignKey` на блюдо с `CASCADE`. Уникальная пара «блюдо и дата», обратная связь `dish.unavailability` |

### Перенос данных ПР №7

`canteen.sqlite3` служит источником. При наличии базы начните со второй
команды. На новом компьютере первая команда создаст источник из рабочего
JSON, а при его отсутствии — из начального набора.

```bash
python3 -m db.import_json
python3 manage.py migrate
python3 manage.py import_pr7
python3 manage.py showmigrations
```

Импорт сохраняет идентификаторы посетителей, блюд и заказов, их связи
и исключения по датам. Он рассчитан на пустую базу Django. Путь к другому
источнику можно передать через `--source`. Оба локальных файла базы
исключены из Git.

### Операции с заказами

```bash
python3 manage.py set_order Bob Soup --date 2026-12-01
python3 manage.py set_order Bob Pizza
python3 manage.py cancel_order Bob
```

Первая команда создаёт заказ, вторая обновляет блюдо и дату, третья меняет
статус на «Отменён» и сохраняет запись. Без `--date` используется текущая дата.
Команды работают с зарегистрированными посетителями и доступными блюдами.
Если нужна только смена статуса на «Выполнен», это можно сделать в админке.
Консольная версия ПР №3 продолжает отдельно работать со своим JSON.

### Запросы ORM

| Сценарий | Выражения |
| --- | --- |
| Меню и карточка блюда | `all`, `get_object_or_404`, поиск по `name__icontains`, фильтр `available`, исключение дат через `exclude` |
| Список заказов | `select_related`, поиск по двум связанным полям через `Q`, фильтр `dish__name`, сортировка по ID, посетителю или цене с дополнительным ID |
| Фильтр и карточка заказа | Список полей через `values` и сортировка по имени, получение заказа по `visitor__name` с загрузкой связей |
| Статистика | `count`, `aggregate` с `Count`, `Sum`, `Min`, `Max`, `Avg`, группировка с `values` и `annotate`, фильтрация по аннотации |
| Навигация | `Paginator` по пять заказов и `querystring` для сохранения параметров |
| Изменение заказов | Поиск посетителя, выбор блюда по названию и доступности, `update_or_create`, `filter().delete()` |

## Настройки и проверка ПР №10

Миграции `menu.0002` и `orders.0002` присваивают существующим блюдам slug,
а старым заказам — статус `active`. У старых заказов дата остаётся пустой,
поскольку в исходных данных её нет. Частичное ограничение сохраняет правило
одного действующего заказа на посетителя и позволяет хранить историю.

При поиске на дату из дневного лимита вычитаются действующие заказы на эту
дату. Отменённые, выполненные и заказы без даты не занимают порции в этой
выборке. Пустой лимит означает отсутствие ограничения по количеству.
Исключение доступности на дату скрывает блюдо из результатов независимо от
остатка. Статистика показывает счётчики всех трёх статусов, а стоимость и
заказы по блюдам считает по действующим заказам.

Чтобы войти в админку, создайте своего локального администратора командой
`python3 manage.py createsuperuser` и откройте `/admin/`. В списках доступны
поиск, фильтры и сортировка. Изменения статусов можно проверить на странице
заказов и в статистике.

Для просмотра SQL через Debug Toolbar установите dev-зависимости и запустите
локальный сервер так:

```bash
python3 -m pip install -r requirements-dev.txt
DJANGO_DEBUG=1 DJANGO_TOOLBAR=1 python3 manage.py runserver
```

Откройте `/orders/` или `/statistics/` и выберите панель **SQL**.
При обычном запуске панель выключена.

## JSON в консольной версии

При отсутствии `canteen_data.json` программа загружает начальные данные
из `initial_data.json`. Изменения сохраняются в `canteen_data.json`
в кодировке UTF-8. Этот рабочий файл исключён из Git. Если рабочий файл
повреждён, программа выведет сообщение об ошибке и сохранит сам файл.

```json
{
  "users": ["Alice", "Bob"],
  "menu": {
    "Pizza": {"price": 10.99, "available": true}
  },
  "orders": {"Alice": "Pizza"}
}
```

`users` хранит список имён, `menu` связывает названия блюд с ценой и
доступностью, а `orders` связывает имя посетителя с названием блюда.
Формат ПР №2 сохранён. При чтении `load_data()` создаёт объекты и связывает
каждый заказ с посетителем и блюдом из загруженных коллекций.
`save_data()` записывает из объектов имена, цены и доступность блюд.
