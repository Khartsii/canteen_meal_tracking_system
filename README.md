# Система учёта питания в столовой

Учебное приложение для учёта питания в столовой. В ПР №5 добавлен
веб-интерфейс Django на основе объектной модели ПР №3. В ПР №6 добавлены
шаблон карточки заказа, общие компоненты и локальные статические файлы.
В ПР №7 веб-версия перешла на SQLite и получила поиск по дате и статистику.

## Возможности консольной версии

- Добавление посетителей и поиск по части имени без учёта регистра.
- Просмотр меню по алфавиту, цены и доступности блюд.
- Просмотр, оформление и отмена заказа посетителя.
- Подсчёт действующих заказов и их общей стоимости.
- Сохранение изменений между запусками.

У посетителя может быть один действующий заказ на одно блюдо.
Для оформления заказа нужно зарегистрировать посетителя и выбрать доступное
блюдо. Цены указаны в долларах, как в исходном примере.

## Веб-интерфейс

Для запуска нужен Python 3.10 или новее. В каталоге проекта выполните:

```bash
python3 -m pip install -r requirements.txt
python3 -m db.import_json
python3 manage.py check
python3 manage.py runserver --insecure
```

Откройте [главную страницу](http://127.0.0.1:8000/). Веб-интерфейс читает
SQLite. Через браузер можно просматривать
данные. Добавление посетителей, оформление и отмена заказов доступны
через консоль.

Флаг `--insecure` включает раздачу CSS, JavaScript и изображения локальным
сервером при `DEBUG=False`. Этот режим позволяет одновременно проверить
собственную страницу 404 и статику на компьютере разработчика.

| URL | Страница |
| --- | --- |
| `/` | Главная страница с навигацией |
| `/menu/` | Список блюд и поиск доступных блюд по дате |
| `/menu/Pizza/` | Цена и доступность блюда. Название в URL подставляется динамически |
| `/orders/` | Действующие заказы, их количество и общая стоимость |
| `/orders/Alice/` | Заказ посетителя с блюдом, стоимостью и статусом. Имя в URL подставляется динамически |
| `/statistics/` | Количество посетителей, цены, итоги и группировки заказов |

Неизвестный адрес, блюдо или заказ возвращает страницу с кодом HTTP 404.

### Шаблоны и маршруты

Представления вызывают `render()` и передают объекты в контекст. Страницы
наследуют `base.html` и заполняют блоки `title` и `content`. Навигация
и подвал подключаются через `include`. Списки используют `for`, проверки
`if` и ветки для пустых коллекций. Фильтры `length`, `floatformat` и
`default` форматируют значения. Ссылки формируются тегом `url` с именами
и пространствами имён `homepage`, `menu` и `orders`.

### Статика

Django находит CSS, логотип и JavaScript в `homepage/static/homepage/`.
Они подключаются тегом `static`. CSS оформляет навигацию и карточки,
JavaScript выводит текущий год в подвале. Bootstrap подключён через CDN.
Представления читают SQLite через `sqlite3` и получают строки `sqlite3.Row`.

## Запуск консоли

Для работы нужен Python 3.10 или новее. В каталоге проекта выполните:

```bash

```

## Объектная модель

| Класс | Атрибуты и поведение |
| --- | --- |
| `Visitor` | Хранит имя `name`. Метод `__str__` возвращает это имя. |
| `Dish` | Хранит название `name`, цену `price` и доступность `available`. Метод `__str__` формирует описание для меню. |
| `Order` | Связывает посетителя `visitor` и блюдо `dish`. Метод `__str__` формирует описание заказа. |
| `Canteen` | Хранит словари объектов `visitors`, `menu` и `orders`. |

Методы `Canteen.add_user()` и `Canteen.find_users()` добавляют и ищут
посетителей. `Canteen.add_order()` проверяет доступность блюда и связывает
в заказе объекты из двух коллекций. `Canteen.info_user()` показывает заказ,
`Canteen.cancel_order()` удаляет его, а `Canteen.order_statistics()`
подсчитывает количество заказов и суммирует цены их блюд.

## SQLite в веб-версии

Импорт создаёт локальный файл `canteen.sqlite3` по схеме `sql/schema.sql`.
По умолчанию источник — рабочий файл `canteen_data.json`, а при его
отсутствии — `initial_data.json`. Можно указать другой источник командой
`python3 -m db.import_json --source путь/к/файлу.json`. После изменений
в консоли повторно запустите импорт, чтобы обновить данные на сайте.
Импорт обновляет справочники по имени, заменяет список действующих заказов
и сохраняет исключения доступности по датам. База создаётся локально
при импорте и исключена из Git.

| Таблица | Поля и ограничения |
| --- | --- |
| `visitors` | `id INTEGER` — первичный ключ, `name TEXT` — уникальное имя |
| `dishes` | `id INTEGER` — первичный ключ, `name TEXT` — уникальное название, `price REAL` ≥ 0, `available INTEGER` (0 или 1) |
| `orders` | `id INTEGER` — первичный ключ, `visitor_id INTEGER` — уникальный внешний ключ на `visitors.id`, `dish_id INTEGER` — внешний ключ на `dishes.id` |
| `dish_unavailability` | `dish_id INTEGER` — внешний ключ на `dishes.id`, `unavailable_date TEXT` — дата YYYY-MM-DD. Составной ключ из обоих полей |

Форма поиска показывает блюда с `available = 1`, для которых на
выбранную дату отсутствует запись в `dish_unavailability`. В исходном
JSON таких исключений нет. Пример добавления исключения в SQLite CLI:

```sql
PRAGMA foreign_keys = ON;
INSERT INTO dish_unavailability (dish_id, unavailable_date)
SELECT id, '2026-12-01' FROM dishes WHERE name = 'Pizza';
```

Десять запросов в `sql/queries.sql` используются веб-представлениями.
Это списки блюд и посетителей, карточка блюда, поиск по дате, список и
карточка заказов, сумма и количество заказов, статистика цен, группировка
блюд по доступности и группировка заказов по блюдам с `HAVING`.
Для запуска файла в CLI выполните `sqlite3 -header canteen.sqlite3`,
затем `.parameter init`, `.parameter set ?1 Pizza` и `.read sql/queries.sql`.
Для проверки запросов с другими параметрами задайте `?1` отдельно перед
соответствующим запросом. Python передаёт параметры через `?`.

## JSON в консольной версии

При отсутствии `canteen_data.json` программа загружает начальные данные
из `initial_data.json`. Изменения сохраняются в `canteen_data.json`
в кодировке UTF-8. Этот рабочий файл исключён из Git. Если рабочий файл
повреждён, программа выведет сообщение об ошибке и сохранит сам файл.

```json
{
  "users": ["Alice", "Bob"],
  "menu": {
    "Pizza": {"price": 10.99, "available": true}
  },
  "orders": {"Alice": "Pizza"}
}
```

`users` хранит список имён, `menu` связывает названия блюд с ценой и
доступностью, а `orders` связывает имя посетителя с названием блюда.
Формат ПР №2 сохранён. При чтении `load_data()` создаёт объекты и связывает
каждый заказ с посетителем и блюдом из загруженных коллекций.
`save_data()` записывает из объектов имена, цены и доступность блюд.
