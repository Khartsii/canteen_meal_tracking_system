# Система учёта питания в столовой

Учебное приложение для учёта питания в столовой. В ПР №5 добавлен
веб-интерфейс Django на основе объектной модели ПР №3.

## Возможности консольной версии

- Добавление посетителей и поиск по части имени без учёта регистра.
- Просмотр меню по алфавиту, цены и доступности блюд.
- Просмотр, оформление и отмена заказа посетителя.
- Подсчёт действующих заказов и их общей стоимости.
- Сохранение изменений между запусками.

У посетителя может быть один действующий заказ на одно блюдо.
Для оформления заказа нужно зарегистрировать посетителя и выбрать доступное
блюдо. Цены указаны в долларах, как в исходном примере.

## Веб-интерфейс

Для запуска нужен Python 3.10 или новее. В каталоге проекта выполните:

```bash
python3 -m pip install -r requirements.txt
python3 manage.py check
python3 manage.py runserver
```

Откройте [главную страницу](http://127.0.0.1:8000/). Веб-интерфейс работает
с тем же JSON, что и консольная версия. Через браузер можно просматривать
данные. Добавление посетителей, оформление и отмена заказов доступны
через консоль.

| URL | Страница |
| --- | --- |
| `/` | Главная страница с навигацией |
| `/menu/` | Список блюд |
| `/menu/Pizza/` | Цена и доступность блюда. Название в URL подставляется динамически |
| `/orders/` | Действующие заказы, их количество и общая стоимость |

Неизвестный адрес или блюдо возвращает страницу с кодом HTTP 404.
HTML формируется шаблонами Django. Для оформления используются CSS и Bootstrap
через CDN. Настройки рассчитаны на локальный запуск.

## Запуск консоли

Для работы нужен Python 3.10 или новее. В каталоге проекта выполните:

```bash
python3 main.py
```

Выберите действие по номеру. Чтобы пройти сценарий ПР №1, выполните
`python3 main.py --demo`. Программа предложит добавить посетителя, затем
покажет доступность пиццы и заказ Alice.

## Объектная модель

| Класс | Атрибуты и поведение |
| --- | --- |
| `Visitor` | Хранит имя `name`. Метод `__str__` возвращает это имя. |
| `Dish` | Хранит название `name`, цену `price` и доступность `available`. Метод `__str__` формирует описание для меню. |
| `Order` | Связывает посетителя `visitor` и блюдо `dish`. Метод `__str__` формирует описание заказа. |
| `Canteen` | Хранит словари объектов `visitors`, `menu` и `orders`. |

Методы `Canteen.add_user()` и `Canteen.find_users()` добавляют и ищут
посетителей. `Canteen.add_order()` проверяет доступность блюда и связывает
в заказе объекты из двух коллекций. `Canteen.info_user()` показывает заказ,
`Canteen.cancel_order()` удаляет его, а `Canteen.order_statistics()`
подсчитывает количество заказов и суммирует цены их блюд.

## Хранение данных

При отсутствии `canteen_data.json` программа загружает начальные данные
из `initial_data.json`. Изменения сохраняются в `canteen_data.json`
в кодировке UTF-8. Этот рабочий файл исключён из Git. Если рабочий файл
повреждён, программа выведет сообщение об ошибке и сохранит сам файл.

```json
{
  "users": ["Alice", "Bob"],
  "menu": {
    "Pizza": {"price": 10.99, "available": true}
  },
  "orders": {"Alice": "Pizza"}
}
```

`users` хранит список имён, `menu` связывает названия блюд с ценой и
доступностью, а `orders` связывает имя посетителя с названием блюда.
Формат ПР №2 сохранён. При чтении `load_data()` создаёт объекты и связывает
каждый заказ с посетителем и блюдом из загруженных коллекций.
`save_data()` записывает из объектов имена, цены и доступность блюд.
